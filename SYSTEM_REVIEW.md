## 2. База данных — модель TaxEvent

Каждое налоговое событие в базе хранит:

| Поле | Тип | Описание |
|---|---|---|
| `date` | DateTime | Дата дедлайна (фактическая, с учётом переносов) |
| `originalDate` | DateTime? | Исходная дата по НК (до переноса из-за выходных) |
| `year` / `month` | Int | Год и месяц (вычисляются из `date`) |
| `taxType` | Enum | Тип налога (НДС, прибыль, и т.д.) |
| `eventType` | Enum | REPORT / PAYMENT / BOTH |
| `isPublished` | Boolean | Опубликовано (виден пользователям) |
| `isDraft` | Boolean | Черновик (противоположен isPublished) |
| `isPostponed` | Boolean | Флаг переноса дедлайна |
| `postponeReasonRu/En/Uz/Uzc` | String? | Причина переноса на 4 языках |
| `orgTypes` | OrgType[] | Кому показывать (пустой = всем) |
| `taxRegimes` | TaxRegime[] | Какому режиму (пустой = любому) |
| `requiresEmployees` | Boolean? | null = неважно / true = только с сотрудниками |
| `requiresAssets` | String[] | Нужные активы (пустой = всем) |
| `requiresSpecial` | String[] | Нужные спецдеятельности (пустой = всем) |
| `requiresPension` | String[] | Нужные пенсионные основания (пустой = всем) |
| `isRecurring` | Boolean | Повторяющееся событие |
| `recurrence` | String? | ONCE / MONTHLY / QUARTERLY / YEARLY |

### Типы налогов (taxType)
`VAT` · `PERSONAL_IT` · `PROFIT` · `PROPERTY` · `LAND` · `WATER` · `EXCISE` · `SOCIAL` · `INPS` · `TURNOVER` · `RENT` · `FEES` · `OTHER`

## 4. Онбординг (9 шагов)

Каждый новый пользователь проходит онбординг. До его завершения (`onboardingDone = false`) показываются ВСЕ события без фильтрации.

| Шаг | Экран | Кому показывается | Что сохраняется |
|---|---|---|---|
| 1 | Приветствие + имя | Всем | `name` |
| 2 | Тип организации | Всем | `orgType` |
| 3 | Режим налогообложения | Только LLC/JSC/IE | `taxRegime` |
| 4 | Есть ли сотрудники | LLC/JSC/IE/FARM | `hasEmployees` |
| 5 | Активы (имущество, земля, вода) | LLC/JSC/IE/FARM | `assets[]` |
| 6 | Специфичная деятельность | Все кроме SELF_EMPLOYED | `specialActivities[]` |
| 7 | Пенсионный фонд | Только если hasEmployees=true | `pensionFund[]` |
| 8 | Напоминания + язык | Всем | `reminderDays[]`, `language` |
| 9 | Итог + CTA на PRO | Всем | — (завершение, редирект на dashboard) |

### Значения активов (шаг 5)
Пользователю предлагаются варианты:
- `"PROPERTY"` — Имущество на балансе
- `"LAND_NON_AG"` — Земля несельхозназначения
- `"LAND_AG"` — Земля сельхозназначения
- `"WATER_USAGE"` — Водные ресурсы

> Для FARM автоматически проставляются `["LAND_AG", "WATER_USAGE"]`

### Значения спецдеятельностей (шаг 6)
- `"NON_RESIDENT_INCOME"` — Выплаты нерезидентам
- `"DIVIDENDS"` — Дивиденды / проценты
- `"ALCOHOL_TOBACCO"` — Алкоголь, пиво, табак
- `"EXCISE"` — Подакцизные товары (скрыто для FARM и TURNOVER)
- `"SUBSOIL"` — Добыча ископаемых (скрыто для FARM и TURNOVER)
- `"HIGH_REVENUE_20B"` — Доход > 20 млрд (только для VAT, не FARM)
- `"CFC"` — КИК (скрыто для FARM)
- `"CONTROLLED_TRANSACTIONS"` — Контролируемые сделки (скрыто для FARM)
- `"ONLINE_KKT"` — Онлайн-ККТ (скрыто для FARM)

### Значения пенсионного фонда (шаг 7)
- `"DISABLED_CHILD_EMPLOYEE"` — Ребёнок-инвалид до 16 лет
- `"LOSS_OF_BREADWINNER"` — Потеря кормильца / трудовое увечье

## 5. Логика фильтрации событий (event-filter.ts)

**Фильтрация НЕ применяется если:**
- Онбординг не завершён (`onboardingDone = false`)
- Тип организации = `ACCOUNTANT`

**При активной фильтрации применяется 6 условий (AND):**

1. **orgType**: Событие показывается если `orgTypes` пустой ИЛИ содержит тип пользователя
2. **taxRegime**: Событие показывается если `taxRegimes` пустой ИЛИ содержит режим пользователя *(не применяется для SELF_EMPLOYED и FARM)*
3. **requiresEmployees**: Показывается если `requiresEmployees = null` ИЛИ совпадает с `hasEmployees` пользователя
4. **assets**: Показывается если `requiresAssets` пустой ИЛИ у пользователя есть хотя бы один из требуемых активов
5. **specialActivities**: Показывается если `requiresSpecial` пустой ИЛИ у пользователя есть хотя бы одна из требуемых деятельностей
6. **pensionFund**: Показывается если `requiresPension` пустой ИЛИ у пользователя есть хотя бы одно совпадение

## 6. Интерфейс календаря

### Режимы отображения
- **Вид "Месяц"** — сетка 7×N, цветные точки на днях с событиями, боковая панель (десктоп) или блок ниже (мобильный)
- **Вид "Список"** — хронологический список событий с цветной левой полосой срочности

### Срочность (urgency)
| Уровень | Когда | Цвет |
|---|---|---|
| overdue | дедлайн прошёл | Красный |
| urgent | 1–3 дня | Оранжевый |
| warning | 4–7 дней | Жёлтый |
| ok | 8+ дней | Зелёный |

### Состояние "Выполнено"
- Авторизованные пользователи могут отметить событие как выполненное
- Хранится в таблице `EventStatus` (per-user per-event)
- Обновляется оптимистично через `/api/events/status`
- Выполненные события: зачёркнутый текст, зелёный фон

### Фильтр по типу налога
Отображаются только те типы налогов, что реально присутствуют в текущем месяце.

### Экспорт (только PRO)
- **ICS** — для Google Calendar / Outlook (`/api/export/ics`)
- **Excel** — (`/api/export/excel`)

- Статья НК

- Флаг "Перенос дедлайна"

**Повторяемость:**

- Кому показывать (checkboxes по orgType), пустое = всем

- Требует активы (checkboxes)
- Требует спецдеятельность (checkboxes)
- Требует пенсионный фонд (checkboxes)

**Секция 3 — Контент (4 языка, табы):**
- Заголовок (обязательно на RU)

## 12. ⚠️ КРИТИЧЕСКИЕ ОШИБКИ В ЛОГИКЕ ФИЛЬТРАЦИИ

> **Это необходимо исправить до запуска в продакшн.**

### Ошибка 1 — Несоответствие ключей активов (assets)

Онбординг сохраняет в БД значения в **ВЕРХНЕМ регистре**:
```
"PROPERTY", "LAND_NON_AG", "LAND_AG", "WATER_USAGE"
```

Но seed-события и форма администратора используют **нижний регистр**:
```
"property", "land_non_agri", "land_agri", "water"
```

**Следствие:** Фильтр `requiresAssets: { hasSome: userAssets }` никогда не совпадает. Пользователь, у которого есть имущество на балансе, **не увидит** события по налогу на имущество и земельному налогу. Вместо этого ему будут показаны только события без условий по активам.

**Файлы с ошибкой:**
- `src/app/[locale]/onboarding/page.tsx` — функции Screen5 (ключи активов)
- `prisma/seed-april-2026.ts` — поля `requiresAssets`
- `prisma/seed-march-2026.ts` — поля `requiresAssets`
- `prisma/seed.ts` — поля `requiresAssets`
- `src/components/admin/event-form.tsx` — значения ASSET_OPTIONS

**Нужно привести к одному стандарту.** Рекомендуется использовать нижний регистр как в событиях (чтобы не менять seed-данные).

---

### Ошибка 2 — Несоответствие ключей специфичных деятельностей (specialActivities)

Онбординг сохраняет в **ВЕРХНЕМ регистре**:
```
"NON_RESIDENT_INCOME", "DIVIDENDS", "ALCOHOL_TOBACCO",
"EXCISE", "SUBSOIL", "HIGH_REVENUE_20B", "CFC",
"CONTROLLED_TRANSACTIONS", "ONLINE_KKT"
```

Seed-события и форма администратора используют **нижний регистр**:
```
"non_resident_income", "dividends", "alcohol_tobacco",
"excise", "subsoil", "high_revenue_20b", "cfc",
"controlled_transactions", "online_kkt"
```

**Следствие:** Все события с условием `requiresSpecial` (их 10+ в апреле) **никогда не показываются** пользователям, даже если те указали соответствующую деятельность при онбординге. Аналогично ошибке #1.

**Файлы с ошибкой:**
- `src/app/[locale]/onboarding/page.tsx` — функции Screen6 (ключи деятельностей)
- Все seed-файлы, компонент `event-form.tsx`

---

### Ошибка 3 — Несоответствие ключей пенсионного фонда (pensionFund)

Онбординг сохраняет:
```
"DISABLED_CHILD_EMPLOYEE", "LOSS_OF_BREADWINNER"
```

Seed-события и форма используют:
```
"disabled_child", "loss_of_breadwinner"
```

**Следствие:** События по пенсионному фонду (10 апр, 27 апр) не показываются соответствующим работодателям.

### Ошибка 4 — EventType.OTHER не существует в схеме Prisma

В `prisma/seed-april-2026.ts` события #16 и #26 (исправление ошибок ККТ) используют `EventType.OTHER`, которого нет в схеме:
```typescript
// Схема Prisma:
enum EventType { REPORT, PAYMENT, BOTH }

// Seed:
eventType: EventType.OTHER  // <- undefined в JavaScript!
```

В JavaScript это обращение вернёт `undefined`, и Prisma примет дефолтное значение `BOTH`. Т.е. события по исправлению ошибок ККТ отображаются как "Отчётность + Уплата" вместо, например, "Прочее".
